Qué esWhat it is

Escribir un CV distinto para cada oferta es lento, y los generadores con IA tienden a adornar la experiencia. CareerCraft parte de la idea contraria: primero construye una base de hechos verificada sobre ti y después redacta a partir de ella con el enfoque más favorable, siempre que siga siendo defendible.

Puedes empezar subiendo tu CV o tu PDF de LinkedIn, o con una entrevista conversacional que solo pregunta por lo que falta. Al pegar una oferta, la app cruza cada requisito con tu perfil (cubierto, implícito con evidencia o ausente), genera el CV en el idioma de la oferta y lo somete a una auditoría antes de dejarte exportarlo.

Funciona de dos maneras con el mismo código: como aplicación web con cuentas de usuario, o como app de escritorio para macOS en la que tus datos no salen del ordenador.

Writing a different CV for every job offer is slow, and AI generators tend to embellish experience. CareerCraft takes the opposite approach: it first builds a verified fact base about you and then writes from it with the most favourable framing that is still defensible.

You can start by uploading your CV or LinkedIn PDF, or through a conversational interview that only asks about what is missing. When you paste a job offer, the app matches each requirement against your profile (covered, implied with evidence, or missing), generates the CV in the offer's language and audits it before letting you export it.

The same code runs in two ways: as a web application with user accounts, or as a macOS desktop app where your data never leaves your computer.

ArquitecturaArchitecture

Un único backend FastAPI concentra toda la lógica: perfil, generación del CV, entrevistas y créditos. La interfaz es una SPA en React que habla con él por REST. Los servicios de dominio son los únicos que tocan la base de datos, el render de PDF y la capa de IA, que elige el proveedor según el modelo: Claude para redactar y auditar, y OpenAI solo para embeddings.

El mismo backend se empaqueta de dos formas. En la versión web corre en un contenedor Docker con PostgreSQL + pgvector y login con JWT. En la app de escritorio, una shell Tauri 2 lanza el backend como proceso local con SQLite y guarda la credencial de IA en el llavero de macOS.

A single FastAPI backend holds all the logic: profile, CV generation, interviews and credits. The UI is a React SPA that talks to it over REST. Only the domain services touch the database, the PDF renderer and the AI layer, which picks the provider by model: Claude to write and audit, and OpenAI for embeddings only.

The same backend ships in two forms. The web version runs in a Docker container with PostgreSQL + pgvector and JWT login. In the desktop app, a Tauri 2 shell launches the backend as a local process with SQLite and keeps the AI credential in the macOS keychain.

Decisiones técnicasTechnical decisions

  • Un backend, dos productos. En lugar de mantener una app web y otra de escritorio, el mismo backend se empaqueta como contenedor o como proceso local de Tauri. Cambian la base de datos (PostgreSQL o SQLite) y la autenticación; la lógica de dominio y sus tests son los mismos.One backend, two products. Instead of maintaining separate web and desktop apps, the same backend ships either as a container or as a local Tauri process. Only the database (PostgreSQL or SQLite) and authentication change; the domain logic and its tests are shared.
  • Antialucinación por capas. Los datos factuales (empresa, puesto, fechas, skills) se copian tal cual; el modelo solo redacta resumen y bullets. Después, un gate audita cada dimensión: los años y el nivel se comprueban con código determinista (los LLM fallaban la aritmética) y la invención o el seniority inflado los revisan jueces LLM con responsabilidades separadas.Layered anti-hallucination. Factual data (company, role, dates, skills) is copied verbatim; the model only writes the summary and bullets. A gate then audits each dimension: years and level are checked with deterministic code (LLMs got the arithmetic wrong) while invention or inflated seniority are reviewed by LLM judges with separate responsibilities.
  • Ni inflar ni quedarse corto. El corrector funciona en las dos direcciones: si un arreglo elimina una exageración pero deja el logro por debajo de lo real, no se acepta. El objetivo es el «punto medio honesto».Neither inflate nor undersell. The corrector works both ways: if a fix removes an exaggeration but undersells the real achievement, it is rejected. The goal is the “honest middle”.
  • Requisitos con evidencia obligatoria. Un requisito solo cuenta como «implícito» si cita un hecho del perfil; si no, pasa a «ausente». La cobertura y el score ATS son deterministas, no una opinión del modelo.Requirements need evidence. A requirement only counts as “implied” if it cites a fact from the profile; otherwise it becomes “missing”. Coverage and the ATS score are deterministic, not the model's opinion.
  • Coste bajo control. Cada tarea usa el modelo que necesita (Haiku para extraer, Sonnet para redactar), con prompt caching y un ledger de créditos atómico. Coste real: unos 10 céntimos de dólar por CV (≈4 céntimos en el banco de evaluación).Cost under control. Each task uses the model it needs (Haiku to extract, Sonnet to write), with prompt caching and an atomic credit ledger. Real cost: about 10 US cents per CV (≈4 cents on the evaluation set).
  • Medir antes que intuir. Desarrollo guiado por specs y ADRs, con un banco de evaluación fijo y una rúbrica de calidad 0–100 que actúa como prueba de regresión antes de cada cambio de prompt o modelo.Measure, don't guess. Spec-driven development with ADRs, a fixed evaluation set and a 0–100 quality rubric that acts as a regression test before every prompt or model change.
